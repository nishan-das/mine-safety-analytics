# Mine Safety Incident Database & Safety Performance Analytics

A SQLite database of mine safety records with a Python layer that computes exposure-normalised injury rates, plus Excel and Streamlit reporting.

> **All data in this project is synthetic** (generated by `create_database.py` with a fixed random seed). No real mine, company, worker or accident is represented; names are randomly assembled.
> Built as a learning project with the help of an AI coding assistant.

## The key finding

Counting accidents hides the real story. Over 12 months (Jul 2025 – Jun 2026) of synthetic data:

| Employment type | Lost-time injuries | Man-hours | LTIFR (per 1M man-hours) |
| --- | --- | --- | --- |
| Contractor | 7 | 439,773 | **15.9** |
| Departmental | 5 | 646,890 | **7.7** |

7 vs 5 injuries look similar, but contractors worked far fewer hours. **After normalising by man-hours, contractors carry about 2× the lost-time injury rate.** Without the exposure table this finding is invisible.

## Database schema (6 tables)

| Table | Contents |
| --- | --- |
| `employees` | 120 named workers: designation, department, Contractor / Departmental |
| `locations` | 12 locations (benches, haul road, workshop, UG faces…), Surface / Underground |
| `shifts` | A / B / C shifts |
| `incidents` | 122 records: fatal, serious, reportable, first aid, near miss; cause category, days lost |
| `monthly_exposure` | persons employed and man-hours worked, per month and employment type |
| `monthly_production` | tonnes produced per month |

## Metrics

| Metric | Definition |
| --- | --- |
| LTIFR | lost-time injuries × 1,000,000 / man-hours worked |
| Severity rate | days lost × 1,000,000 / man-hours worked (a fatality is charged 6,000 days, a common convention; configurable in `safety_metrics.py`) |
| Near-miss ratio | near misses reported per lost-time injury |

Lost-time injuries = Reportable Injury, Serious Bodily Injury and Fatal.

## Files

| File | Purpose |
| --- | --- |
| `create_database.py` | Builds `mine_safety.db` with synthetic data |
| `queries/v1_queries.sql` | 14 SQL queries, from SELECT to multi-table JOINs and the three findings |
| `run_sql.py` | Runs a .sql file or a single query and prints the results |
| `safety_metrics.py` | Version 2: pandas layer computing LTIFR, severity rate, near-miss ratio; writes an Excel report and charts |
| `app.py` | Streamlit dashboard using the same functions |

## How to run

```bash
pip install -r requirements.txt
python create_database.py
python run_sql.py queries/v1_queries.sql
python safety_metrics.py          # -> outputs/safety_report.xlsx + charts
streamlit run app.py              # interactive dashboard
```

## Tools

Python, SQL (SQLite), pandas, Matplotlib, Streamlit, openpyxl.
